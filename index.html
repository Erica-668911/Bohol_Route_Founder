    Execution time and complexity

    Search time / auxiliary space: Brute Force O(nm) worst / O(1); KMP O(n + m) / O(m); Rabin-Karp O(n + m) average, O(nm) worst / O(1); Boyer-Moore bad-character variant O(nm) worst / O(min(m, alphabet size)). Match positions require O(z) output space. RLE is O(n) time and O(n) output space. Dictionary processing is O(n + d log d + dB) time and O(dB) worst-case state space for the 0/1 knapsack, where d is repeated-word candidates and B is dictionary-storage budget. Reservoir sampling is O(n) time and O(k) space. Search, compression, optimization, and sampling show measured browser execution times; results vary by device and input size. Compression size uses UTF-8 bytes and includes the emitted dictionary header.

    Under the hood

    Algorithm and complexity

    1. Graph Representation

    The system represents selected Bohol tourist attractions as vertices of a weighted graph. Connections between attractions are represented as edges. The edge weight represents the distance between two tourist attractions.

    2. Dijkstra's Shortest Path Algorithm

    Dijkstra's Algorithm is used to find the shortest route between the selected starting point and destination. The algorithm repeatedly selects the unvisited vertex with the smallest known distance and updates the distances of its neighboring vertices.

    3. Algorithm Design Technique

    The system uses the Greedy Method. Dijkstra's Algorithm follows a greedy strategy by selecting the currently closest unvisited vertex at every step.

    4. Time Complexity

    The simple implementation used in this project has a time complexity of O(V²), where V represents the number of vertices or tourist spots.

    5. Space Complexity

    The graph and supporting arrays require O(V + E), where V is the number of tourist spots and E is the number of connections between them.
